# 기존 GitHub 샘플과 교육 공동설계 구조 비교

비교 기준은 저장소의 기존 `paper_pipeline_v2` 파이프라인과 이번 PR의 `agent_system`입니다.

## 한눈에 비교

| 비교 항목 | 기존 GitHub 샘플: paper_pipeline_v2 | 이번 업데이트: education-co-design |
|---|---|---|
| 주된 목적 | 논문 생산 자동화 | 180분 수업 공동설계·제작·검수 |
| 중심 단위 | 7단계 파이프라인 | 3개 전문 에이전트와 승인 게이트 |
| 실행 방식 | Stage 1 병렬 처리 후 순차 진행 | 제안 → 사람 승인 → 제작 → 독립 검수 |
| 자동화 강도 | 높음 | 승인 전 제안, 승인 후 제작 |
| 품질 통제 | 100점 GATE, 기본 70점, Stage 4 회귀 | 구조 98점·운영 90점·주차 80점·치명결함 0 |
| 사람 개입 | API 요청 이후 제한적 | 교육 방향과 설계 선택을 교수자가 승인 |
| 실패 처리 | 점수 미달 시 자동 재생성 | 파일 문제는 제작 회귀, 설계 문제는 공동설계 회귀 |
| 기억·상태 | SQLite 작업큐·사용량 상태 | YAML 상태 전이·결정 로그·제안서·검수보고서 |
| 산출물 | 논문 Markdown/DOCX/API 결과 | PPT·실습지·사례·평가자료·교수자 실행안 |
| 적합한 작업 | 반복적인 대량 생산 | 교육적 판단과 현장성을 함께 요구하는 작업 |

## 구조 대응표

| 기존 샘플의 개념 | 교육 공동설계에서의 대응 |
|---|---|
| Stage 1 연구·자료 수집 | EDU-DESIGNER의 근거·기존 자료 확인 |
| Stage 2~5 작성·분석·교정 | EDU-PRODUCER의 자료 구현 |
| Stage 6 평가 | EDU-QA의 근거·운영성·접근성 검수 |
| 70점 GATE | 교수자 승인 + 운영 점수 기준 |
| Stage 4 회귀 | PROPOSAL 또는 BUILD로 회귀 |
| MCP tool 노출 | 향후 각 역할의 읽기·쓰기 도구로 확장 가능 |
| 비동기 job 상태 | 향후 주차별 설계 카드·작업판으로 확장 가능 |

## 무엇을 그대로 수용하고, 무엇을 바꾸었나

### 그대로 수용

- 단계별 책임 분리
- 병목을 줄이는 전문 작업 분배
- 품질 점수와 통과 기준
- 기준 미달 시 회귀
- 작업 상태를 기록하는 구조
- 반복 가능한 템플릿

### 교육 작업에 맞게 바꾼 부분

- 자동 완료 대신 교수자 승인 필수
- 점수만이 아니라 학습자 산출물 확인
- 내용 정확성 외에 특수교육적 접근성 평가
- 180분 시간표를 필수 조건으로 설정
- 단순 재생성 대신 설계 결함과 파일 결함을 분리
- 주차별 전후 연결을 검수 항목으로 추가

## 권장 결합 방향

현재는 두 파이프라인을 합치지 않고 분리하는 것이 안전합니다.

1. `paper_pipeline_v2`의 작업큐·상태 저장·MCP 노출 방식을 공통 인프라 후보로 둡니다.
2. `agent_system`은 교육 설계 규칙과 승인·검수 정책을 담당합니다.
3. 향후 통합할 때는 `education-co-design`을 별도 job type으로 등록합니다.
4. 교수자 승인 없는 자동 배포·자동 완료는 허용하지 않습니다.
